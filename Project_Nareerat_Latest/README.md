# ระบบตอบคำถามที่พบบ่อย (FAQ) การนำส่งข้อมูลกรมธรรม์ประกันภัย (IBSL Policy RAG)

ระบบค้นคืนและตอบคำถามข้อกำหนดการนำส่งข้อมูลกรมธรรม์ประกันภัย ด้วยเทคนิค **Retrieval-Augmented Generation (RAG)** บนเว็บแอปพลิเคชัน Localhost พร้อมระบบประเมินผลโดยมนุษย์ (**Human-in-the-Loop**) และคำแนะนำประกอบจาก **AI Agent** ภายนอก

---

## 📌 คุณสมบัติเด่นของระบบ

1. **คัดกรองเฉพาะข้อมูล Policy และตารางย่อยของกรมธรรม์อย่างแท้จริง**
   - รวมข้อมูล 14 ตาราง ได้แก่ `Policy`, `Customer`, `Insured`, `InsuredBeneficiary`, `SubPolicy`, `PolicyCovPlanSeq`, `CoveragePlanCoverage`, `Coverage`, `Beneficiary`, `Endorsement`, `Loan`, `LoanPayment`, `Investment`, `PolicyFundCode` รวมทั้งสิ้น **204 ฟิลด์**
   - รวมคำถาม-คำตอบ FAQ กรมธรรม์ **21 รายการ** จากไฟล์ต้นฉบับ
   - **ตัดข้อมูลส่วน Payment และ Claim ออกทั้งหมด** ตามข้อกำหนด

2. **ระบบค้นคืนแบบผสมผสาน (Hybrid RAG: Exact & Semantic)**
   - รองรับทั้งการค้นหาชื่อฟิลด์ภาษาอังกฤษ (เช่น `pol_start_date`, `pol_status`, `insrd_birthday`)
   - รองรับการค้นหาความหมายภาษาไทยและคำถามทั่วไป (เช่น "วันที่เริ่มต้นความคุ้มครอง", "กรมธรรม์ที่เป็น Expiry ส่งสถานะอะไร")
   - ใช้การตัดคำภาษาไทย (PyThaiNLP) ร่วมกับ Character n-grams และ TF-IDF Cosine Similarity
   - ป้องกันเอกสารซ้ำและค้นคืนสูงสุด 3 รายการที่มีความเกี่ยวข้องที่สุด

3. **สังเคราะห์คำตอบภาษาไทย (LLM Synthesis & Fallback)**
   - สังเคราะห์คำตอบภาษาไทยโดยอ้างอิงรหัสรายการ `[id]` จากฐานความรู้ภายในเท่านั้น
   - รองรับทั้ง Google Gemini API (`GEMINI_API_KEY`) และ OpenAI API (`OPENAI_API_KEY`)
   - **กรณีไม่มี API Key:** ระบบยังคงทำงานได้ 100% โดยสรุปสาระสำคัญโดยตรงจากหลักฐานที่ค้นคืนได้จริง พร้อมแจ้งสถานะอย่างโปร่งใส ไม่มีการแต่งเงื่อนไขหรือสร้างคำตอบจำลอง

4. **AI Agent สำหรับคำแนะนำจากแหล่งภายนอก**
   - ดึงข้อมูลประกอบจากเว็บไซต์ทางการที่เชื่อถือได้ (เช่น คปภ. `oic.or.th`, `sec.or.th`)
   - แสดงลิงก์อ้างอิงภายนอกที่เปิดได้จริง
   - ยึดข้อกำหนดว่าข้อมูลภายนอกไม่ถูกใช้แก้ไขหรือแทนที่โครงสร้าง IBSL ในฐานความรู้

5. **Human-in-the-Loop Evaluation (การประเมินโดยมนุษย์)**
   - ผู้ใช้สามารถประเมินผลการค้นคืนแต่ละรายการว่า "เกี่ยวข้อง" หรือ "ไม่เกี่ยวข้อง"
   - บันทึกผลประเมินและความคิดเห็นลงฐานข้อมูลถาวร SQLite (`storage/database.sqlite`)
   - ปรับปรุง/แก้ไขผลประเมินเดิมได้โดยไม่ทำให้ข้อมูลซ้ำซ้อน

6. **การประเมินประสิทธิภาพระบบ (System Evaluation Metrics)**
   - แสดงการ์ดสรุปตัวชี้วัด 3 ค่าในแถวเดียวบนคอมพิวเตอร์และเรียงลงบนมือถือ:
     1. **Precision@3** (Macro-average เทียบกับ Ground Truth)
     2. **Recall@3** (Macro-average เทียบกับ Ground Truth)
     3. **F1@3** (คำนวณต่อคำค้นก่อนนำมาเฉลี่ยแบบ Macro-average)
   - อ้างอิงชุดทดสอบมาตรฐานที่ผ่านการตรวจรับรองใน `data/ground_truth.json`
   - ยังคงเก็บบันทึกประวัติและฟังก์ชันประเมินโดยผู้ใช้ (Human-in-the-Loop) ในหน้าค้นหาและตารางประเมินไว้ครบถ้วน

7. **หน้าจอตามสไตล์อ้างอิง (3 หน้าจอ)**
   - พื้นหลังสีเทาอ่อนอมฟ้า (`#EEF2F6`)
   - การ์ดเนื้อหาหลักสีขาว ขอบโค้งมน (`rounded-3xl`) เงาบาง
   - เมนูด้านซ้ายกะทัดรัด ไอคอนสวยงาม รองรับทั้งมือถือและเดสก์ท็อป

## 🛠️ ขั้นตอนการติดตั้งและเปิดใช้งาน

### 1. ความต้องการของระบบ
- **Python:** เวอร์ชัน 3.10 ขึ้นไป (เช่น Python 3.11, 3.12, 3.15)
- ไม่จำเป็นต้องมี Node.js ระบบสามารถทำงานได้สมบูรณ์ผ่าน Python FastAPI

### 2. ติดตั้ง Dependencies
เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วรันคำสั่ง:

```bash
pip install -r requirements.txt
```

*(หรือหากใช้พาธของ Python เฉพาะ เช่น `python -m pip install -r requirements.txt`)*

### 3. ตรวจสอบไฟล์ข้อมูลในโฟลเดอร์ `data/`
ไฟล์ข้อมูลเริ่มต้นถูกวางไว้ในโฟลเดอร์ `data/` เรียบร้อยแล้ว ได้แก่:
- `data/FAQ.xlsx`
- `data/Fields_4.0.csv` / `data/Fields_4.0.xlsx`
- `data/ground_truth.json`

ระบบจะโหลดและสร้างดัชนีอัตโนมัติเมื่อเปิดเซิร์ฟเวอร์ครั้งแรก ไม่จำเป็นต้องอัปโหลดไฟล์ซ้ำ

### 4. การตั้งค่า API Key (ไม่บังคับ)
คัดลอกไฟล์ `.env.example` ไปเป็น `.env`:

```bash
copy .env.example .env
```

เปิดไฟล์ `.env` แล้วกำหนดค่าตามต้องการ:

```ini
# เลือกระบุ API Key (หากเว้นว่างไว้ ระบบค้นคืนภายในจะทำงานปกติและแสดงข้อมูลที่ค้นคืนได้โดยตรง)
GEMINI_API_KEY=your_gemini_api_key_here
OPENAI_API_KEY=
TAVILY_API_KEY=your_tavily_api_key_here

# พอร์ตสำหรับรันเว็บเซิร์ฟเวอร์ (ค่าเริ่มต้น 8000)
PORT=8000
```

### 5. เปิดเซิร์ฟเวอร์ใช้งาน
รันคำสั่ง:

```bash
python run_server.py
```

หรือใช้ uvicorn โดยตรง:

```bash
uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

เมื่อเปิดสำเร็จ หน้าต่าง Terminal จะแสดงข้อความ:
```
==================================================================
🚀 เริ่มต้นระบบ IBSL Policy FAQ RAG Server
📍 เว็บไซต์พร้อมใช้งานที่: http://127.0.0.1:8000
📖 ขอบเขตข้อมูล: เฉพาะข้อมูล Policy (ไม่รวม Payment และ Claim)
==================================================================
```

เปิดเว็บเบราว์เซอร์ไปที่: **[http://localhost:8000](http://localhost:8000)**

## 🔄 การสร้างดัชนีใหม่ผ่านหลังบ้าน (Re-indexing)

หากมีการแก้ไขหรือเปลี่ยนแปลงไฟล์ในโฟลเดอร์ `data/` สามารถสั่งสร้างดัชนีใหม่ได้ทันทีผ่านคำสั่งหลังบ้านโดยไม่ต้องเพิ่มหน้าจอจัดการข้อมูล:

**วิธีที่ 1: ผ่านคำสั่ง cURL ใน Terminal**
```bash
curl -X POST http://localhost:8000/api/reindex
```

**วิธีที่ 2: ผ่าน Python script**
```bash
python -c "import urllib.request; urllib.request.urlopen(urllib.request.Request('http://localhost:8000/api/reindex', method='POST'))"
```

**วิธีที่ 3: กดปุ่ม "รีเฟรชดัชนี" ที่มุมขวาบนของหน้าเว็บ**

## 🧪 การทดสอบระบบ (Automated Tests)

รันชุดทดสอบความถูกต้องของระบบด้วยคำสั่ง:

```bash
python -m unittest discover -s tests -v
```

ผลการทดสอบจะครอบคลุม:
1. การคัดกรองเฉพาะ Policy data (ตัด Payment และ Claim ออก)
2. การค้นหาชื่อฟิลด์ตรงตัวและคำถามภาษาไทย
3. การตัดข้อมูลซ้ำและแสดงผลไม่เกิน 3 รายการ
4. การบันทึกและแก้ไขผลประเมินใน SQLite โดยไม่เกิดข้อมูลซ้ำซ้อน
5. การคำนวณ Ground Truth Metrics (TP, FP, FN, Precision, Recall, F1)
6. การคำนวณ User Precision@3 จากผลประเมินมนุษย์
7. กรณีที่ไม่มี LLM หรือ Web Search API keys ทำงานได้อย่างปลอดภัย

## 📊 ระเบียบวิธีการประเมินผลและคำนวณ Metrics

| ตัวชี้วัด | คำอธิบายและสูตรการคำนวณ |
|---|---|
| **คะแนนความคล้าย (Similarity Score)** | คำนวณจาก **Cosine Similarity** ของเวกเตอร์ข้อความ โดยแปลงเป็นเปอร์เซ็นต์ $(0 - 100\%)$ เพื่อแสดงความใกล้เคียงของเนื้อหา **ไม่ใช่ความถูกต้อง (Accuracy)** ของระบบ |
| **User Precision@3** | คำนวณเฉพาะคำค้นที่ผู้ใช้ประเมินครบทั้ง 3 รายการ โดยใช้สูตร: $\text{Precision@3} = \frac{\text{จำนวนรายการที่เกี่ยวข้อง}}{\text{จำนวนรายการที่แสดงจริง (สูงสุด 3)}}$ โดยไม่นำรายการที่ยังไม่ได้ประเมินมานับเป็นไม่เกี่ยวข้อง และไม่คำนวณ Recall หรือ F1 จากการกด 3 รายการของผู้ใช้ |
| **Ground Truth Benchmark** | ประเมินกับชุดคำถามที่มีเฉลยรายการที่เกี่ยวข้องทั้งหมด ($GT$) เทียบกับรายการที่ระบบค้นคืน 3 อันดับแรก ($RET$):<br>• $TP = \|RET \cap GT\|$<br>• $FP = \|RET \setminus GT\|$<br>• $FN = \|GT \setminus RET\|$<br>• $\text{Precision} = \frac{TP}{TP + FP}$<br>• $\text{Recall} = \frac{TP}{TP + FN}$<br>• $F_1 = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$<br>และแสดงผลเฉลี่ยแบบ Macro-average |
