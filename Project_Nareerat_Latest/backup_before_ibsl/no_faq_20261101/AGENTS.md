# AGENTS.md — guide for AI coding agents

Read this before changing anything. `README.md` is the original Thai user manual and is partly
out of date (it says 204 fields / 33 FAQs / top-3 results); this file describes the code as it is.

## What the system is

A localhost RAG web app that answers questions about the Thai insurance regulator's (OIC / คปภ.)
**IBSL Policy data-submission spec**: which field to send, its meaning, type, and submission rules.

- Knowledge base: **209 Policy fields in 14 tables** + **36 in-scope FAQs**. Payment and Claim data are out of scope by design.
- Stack: Python FastAPI backend, single-page frontend (plain JS + Tailwind CDN + Lucide icons), SQLite, no Node build.
- UI and all user-facing text are **Thai**. Keep new user-facing text in Thai.
- Not a git repository. There is no version control: back up files before large edits.

## Run / test

```bash
pip install -r requirements.txt
python run_server.py                        # http://127.0.0.1:8000 (PORT in .env)
python -m unittest discover -s tests -v     # unit tests (11), use a temp SQLite DB, safe to run
python scripts/build_rag_dataset.py         # rebuild data_rag/ from data/
python scripts/build_ibsl_dataset.py        # rebuild data_rag/ibsl_* from the IBSL-PR-INC PDF; prints + writes data_rag/IBSL_REPORT.md (all checks must PASS); needs pip install pypdf pdfplumber pypdfium2
python scripts/export_feedback_to_ground_truth.py [--merge]
```

`tests/test_live_server.py` hits a running server on port 8000 and writes searches to that server's DB.
To test against a throwaway server: start uvicorn on another port with `IBSL_DB_PATH=<temp file>`.

Windows note: `curl` in Git Bash mangles Thai JSON bodies (searches silently return 0 results).
Use Python `urllib` with explicit UTF-8 for API tests. Set `PYTHONIOENCODING=utf-8` when printing Thai.

## Layout

```
backend/rag_engine.py   RAGEngine: data loading, TF-IDF index, scoring, LLM answer, web search, GT evaluation
backend/main.py         FastAPI routes + static frontend serving
backend/database.py     SQLite: search history, user evaluations, user metrics, feedback aggregation
frontend/index.html     4 views: view-home, view-search, view-fields, view-metrics (switchTab())
frontend/app.js         all UI logic
data/                   ORIGINAL source files — never modify (Fields_4.0.csv/.xlsx, FAQ.xlsx, ground_truth.json)
data_rag/               RAG-ready copy GENERATED by scripts/build_rag_dataset.py — do not hand-edit, regenerate
scripts/                build_rag_dataset.py, export_feedback_to_ground_truth.py
storage/                database.sqlite (real user data), index_cache.pkl + knowledge_base.json (index cache)
```

## Data pipeline

1. `data/` → `scripts/build_rag_dataset.py` → `data_rag/` (`fields.json`, `tables.json`, `faqs.json`,
   `corpus.jsonl`, `glossary.json`, `ground_truth.json`, `DATA_REPORT.md`).
   The script cleans Thai text, adds aliases/keywords (hand-written dicts `TABLE_META`, `GLOSSARY`,
   `FIELD_ALIASES`), fixes 4 broken descriptions (`DESC_FIXES`), links FAQs to fields, marks
   out-of-scope FAQs (`FAQ_OUT_OF_SCOPE`), and chunks long FAQs (chunks are only in `corpus.jsonl`; the engine uses whole FAQs).
2. `RAGEngine.load_raw_data()` uses `data_rag/` when present (`load_rag_data()`), else parses `data/`
   directly. Force the original with `IBSL_DATA_SOURCE=original`.
3. The index cache stores a `data_signature()` (source kind + file mtimes/sizes). A mismatch triggers a
   rebuild automatically on startup; `POST /api/reindex` forces one.

IDs are stable and shared by search results, SQLite and ground truth: `FIELD-<field_name>`,
`FAQ-POL-NN` / `FAQ-MAN-NN` / `FAQ-GEN-NN` (NN = Excel row − 1, so gaps are possible).

## Search pipeline (`/api/search`)

1. `get_query_feedback(query)` — net user votes for this exact query (case/whitespace-insensitive).
2. `search_structured(query, feedback=...)`:
   - `search_fields`: hand-tuned additive scoring — exact/prefix/substring name match (+35/+18/+12…),
     table name, description (+30 exact … +2.5 token), condition, aliases (`ALIAS_*_BONUS`),
     plus TF-IDF cosine × 4. Then `cut_weak_tail`: keep ≥ 50% of top score, max 10.
   - `apply_user_feedback`: net < 0 → hidden; net > 0 → moved to top (re-added if cut off).
   - `search_faqs_for_fields`: FAQs linked through STRONG fields only (≥ 50% of top field), capped
     description hits, `FAQ_MIN_SCORE`, cut to max 5.
   - Each field gets `faq_answers` (FAQs mentioning the field name).
3. Per-field LLM explanation, then an overall answer from fields + FAQs (Gemini or OpenAI; deterministic
   Thai fallback when no key). Tavily web search adds an external recommendation.
4. Only **fields** are displayed, saved (`query_items`, `rank_no` = display order) and user-evaluable.
   FAQs are shown inside field cards, not as a separate list.

All tunables are module constants at the top of `rag_engine.py`. Change them there, not inline.

## Evaluation — two separate things

- **Ground Truth benchmark** (`evaluate_ground_truth`, `data/ground_truth.json`, 8 cases): uses
  `search_ranked(q, k=3)` = true top-3 across fields+FAQs, FAQ score capped just below the field it
  came through. Macro P/R/F1@3. **Deliberately ignores user feedback** — do not wire feedback into it,
  or feedback-derived ground truth becomes circular (trivially 100%).
  Current: P 0.792 / R 0.833 / F1 0.767 (baseline on original data, fresh index: 0.604 / 0.708 / 0.629).
  The 3 KPI cards and the strip under the search box show these numbers.
- **User evaluation** (`get_user_precision_metrics`): P@3 over ranks 1–3 only, counted only when all
  top-3 items were rated; also "Precision (ทั้งหมด)" over all displayed items when all were rated.
  No recall/F1 from user clicks (the full relevant set is unknown).
- `export_feedback_to_ground_truth.py` turns fully-rated queries into candidates in
  `data/ground_truth_candidates.json`; `--merge` appends to `data/ground_truth.json` (backup kept).
  Candidates need human review — user ratings are sometimes questionable.

## API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/status` | counts, LLM/web-search configuration |
| POST | `/api/search` | `{query, top_k?}` → fields, faqs, answer, `feedback_applied`, `query_id` |
| POST | `/api/evaluate` | `{query_id, evaluations:[{item_id, relevance 0/1}], comment?}` |

## Rules for agents

- **Never modify `data/` source files** (Fields CSV/XLSX, FAQ.xlsx). Change `scripts/build_rag_dataset.py` and regenerate `data_rag/`.
- **Never write test data into `storage/database.sqlite`** — it holds real user evaluations. Use `IBSL_DB_PATH`.
- **Never print, copy or commit API keys.** `.env` and (currently) `.env.example` contain real-looking keys that should be revoked.
- Don't tune scoring against the 8 ground-truth cases alone; it overfits. Check a broader query set
  (e.g. ทุนประกัน, เบี้ยประกัน, คืนเงินกู้, วันเกิด, pol_id, xyzabc12345 → must return nothing) for regressions.
- Exclusion of Payment/Claim tables is by table-name **prefix** — the "Loan Payment" table is Policy data and must stay.
- The user asked for no version numbers ("4.0") and no "209 ฟิลด์" in UI text. Keep counts dynamic (`/api/status`, `/api/fields`).
- Tests encode the requirements (field/FAQ counts, cut-off behaviour, feedback, metrics). Update tests together with intentional behaviour changes.
- After editing `frontend/app.js`, run `node --check frontend/app.js`. A syntax error there disables every button in the UI.

## Known limitations (not yet solved)

- Ground truth has only 8 cases and predates 4 newer FAQs → scores are noisy and likely optimistic.
- Aliases, description fixes and FAQ categories in `data_rag/` were written without an IBSL expert; see `data_rag/DATA_REPORT.md`.
- Lexical/rule-based retrieval: no embeddings or reranker; paraphrases without alias coverage fail.
- Spec covers v4.0 fields only, while some FAQs reference v4.01–4.11 fields (listed in `DATA_REPORT.md`).
- Feedback applies only to the identical query text; one rating changes results for everyone.
- No auth: anyone reaching the server can delete all evaluations.
- LLM answers are not checked against the retrieved evidence.
